# 表达、术语与排版

## 1. 中文表达与技术名称

每个自然段先指出讨论的对象，再写动作、发生条件及结果。一段只推进一个判断。含有多项操作时按顺序列出。润色前通读相邻内容，按原意重新组织句子，保留数字、适用条件、路径、命令和日志原文。

- 把“对文件进行校验”改成“校验文件”。把“任务异常，系统兜底”改成具体行为，例如“文件生成失败后，任务页显示失败原因”。后一句描述的是虚构导出服务。
- 用直接陈述替换空泛的总起、总结、无依据的让步和反问。保留会改变读者判断的限制。项目还没有测量某个环节时，写明缺哪项数据、怎样取得。
- 给出最终的设计与行为。变更过程属于版本记录，故障时间线属于复盘。多个可行方案分别写清适用条件，分期交付写清每期能独立验收的范围。
- 遵循规范、源码和同行采用的名称。保留英文专业术语，在首次出现时用中文解释。专业术语需要使用中文译名时附英文原名。请求、缓存等已有通用中文名称的词沿用中文。
- 一个概念使用一个名称，一个符号表示一种对象。简称首次出现时定义。字段、命令、错误信息等使用原文并标为代码。名称要说明用途，避免自造译名、缩略语、隐喻和数量加泛称。

### 1.1 中文稿用词核对

逐句检查候选词的语境。以下是规范约束的中文叙述用语，逐字引用和技术标识保留原样。

- 单字或缩略说法如“栈”“死”“拆”“落”，按语境写出具体含义，例如用 `call stack` 指调用记录，用“进程终止”描述执行结果。“自然段”用全称。“粗、细、硬、软、实、虚、判”按规范使用含义明确的复合词，如“详细”“实际”“判定”。
- 避免“契约、走读、总账、打挂、炸了、翻车、牙齿、第一刀、凿接缝、喂给、全程证明、放心提交、原文粘贴”。直接说明接口约定、调用顺序、失败现象、改动或验证范围。
- 删除“一句话总结、总之、综上、总的来说、简而言之、换句话说、下面详细、如上所述、以上内容、上述内容”等套语。去掉为强调而加的“而不是、而非”。
- 避免“第一版、稳妥、激进、硬编码、实操、夯实、扎实、虚空”等笼统表达。写出实际范围、固定值、操作和证据。
- 将“落地、闭环、抓手、赋能、拉通、打通、沉淀、颗粒度”换成具体动作或对象。“对齐”保留内存对齐等技术含义。避免用“轴、面”创造项目外无法检索的名称。

## 2. 标题与 Markdown

标题同时点出对象和讨论的方面。例如用“导出任务的下载条件”，读者可以据此查找文件何时可用。标题用中性的名词短语，按内容命名。较长技术文档按章、节连续编号，交叉引用同时标出目标名称。短文沿用已有模版的层次。

Markdown 使用一个一级标题，逐级安排下属标题。正文、列表、表格和代码块之间空一行。中文与英文或数字间留空格。代码块标注语言，公式给出变量和单位，仓库内链接用相对路径。移动章节后复查引用，在目标渲染器查看实际效果。

## 3. 图、表与图解

架构图表达组件连接，流程图表达步骤和分支，时序图表达参与方的消息顺序，状态图表达事件触发的转换，实体关系图表达对象间的对应关系。一句话能说清的关系用文字说明。

使用可编辑图源并与正文一起保存。总览图只显示全局关系。分场景图先交代具体场景，每张图画一个场景。必须按次序执行的操作标号，同时或任选的动作注明含义。节点用完整名称，角色配色、单位与正文一致。每张图后附图解，按顺序写出动作发起方，并点出图里看不出的一个条件、时差或失败点。引用外部图片时核对版本与许可并标出来源。

表格适合并列比较、逐项核对、索引和二维对应。把推理放在正文中，表内各行比较同类对象。列名写明单位，缺失数据说明原因。带有图、表或公式的稿件要在实际阅读界面检查换行、裁切和连线。
