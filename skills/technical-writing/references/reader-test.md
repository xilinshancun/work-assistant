# 成稿检查与读者测试

## 1. 审阅大纲

新建或大幅改写文档时，请读者代表、决定人或审阅者看大纲。对方应能指出谁读、要完成什么动作、每节回答什么、需要哪组例子，以及哪些事项需要决定。先解决范围、顺序和抽象层次的问题。局部文字修订直接检查受影响的内容。

## 2. 成稿检查

- 从主要读者的起点顺读。每个设计能找到它要解决的问题，每个新概念在第一次需要时已有定义。遇到需要猜测的步骤，补上前提或例子。
- 逐项核对影响结论的来源、版本、引用范围和责任人。用独立计算复核正文、表格及图中的数字，检查贯穿示例的编号、单位、时间和状态变化。
- 在说明的环境运行给读者的命令，比较实际输出与示例。对照固定版本检查源码节选和配置。按目标格式渲染图、表与公式，打开相关链接。发布到不同载体时也核对最终载体。
- 用短表记录检查对象、方法、实际结果与能确认的范围。尚未执行的检查注明原因。将检查记录与成稿一起交给审阅者。

## 3. 独立读者测试

新建或大幅改写时，为每类主要读者选择一位没有参与写作的人或新会话 agent。只交给对方读者背景、文档和问题。让对方完成代表性的任务，交回答案、需要猜测的步骤和遇到的矛盾。作者另外保留预期答案。

例如，给第一次使用虚构导出服务的读者一个任务编号，请对方写出从取得编号到下载文件的操作，并判断生成失败时能查到什么。读者若把“拿到编号”当成“文件已就绪”，就回到首次介绍两者的位置补充触发条件和示例。

对照实际表现定位原因，区分缺少背景、概念混淆、步骤跳跃、例子不足与措辞含糊。修改后用一位新读者复测同一问题。记录读者背景、任务、实际回答和修改结果。

## 4. 发布后的反馈

记录反馈对应的读者、日期和正文位置。事实有误就更正，解释不清就改写，范围以外的问题给出去处。同类问题出现两次，或一次反馈揭示多处问题时，检查全文，留下可以复用的规则和改写示例。
