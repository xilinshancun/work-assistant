# 文档设计与讲解

## 1. 读者、问题和大纲

为每类主要读者写下一行，记录角色、读完要做的事、已有知识、容易卡住的地方和需要读的章节。把读者的话按顺序写成问题。短文可以只有一个问题。长文为每个问题安排一节，需要另一篇才能回答的给出具体位置。保留这组问题，交付时用它做读者测试。

例如，在一个虚构的导出服务中，使用者依次要知道怎样提交导出、怎样查询进度、何时可以下载。维护者还需要定位生成文件失败的步骤。前一条阅读路线可以在成功下载处结束，后一条从同一个示例进入内部流程。

| 读者要完成的事 | 文档类型 | 正文的顺序 |
| --- | --- | --- |
| 跑通一次操作 | 接入或使用指南 | 必要前提、一次完整的最小操作、可见结果、参数变化和常见错误 |
| 解释一种机制或独立计算结果 | 教案 | 熟悉的问题、整体模型、分步推理、可自行改变条件的例子 |
| 判断技术方向与自身工作的关系 | 导读或行业分析 | 熟悉的背景、发生的变化、由此产生的问题、论点，再讲概念、现状、机制、案例和局限 |
| 实现并验收功能 | 需求文档 | 问题与目标、角色与场景、业务规则和验收条件、非功能要求和各期范围 |
| 评审架构或实现接口 | 系统设计 | 核心需求、共同概念、端到端例子、架构与责任边界、接口、内部设计 |
| 在会上作决定 | 讨论材料 | 决策所需的背景、待定事项、可行选项、各选项的后果与依据、建议和决定人 |
| 验证故障原因和改进效果 | 复盘 | 影响、时间线、原因证据、修复、验证结果和改进项 |
| 据证据选择方案 | 调研报告 | 问题与约束、候选方案、在相同条件下的比较、结论和重新选择的条件 |

项目已有模版时，把读者的问题放进模版规定的章节。大纲应能让读者代表判断内容够不够、先后顺序能否跟上、需要确认哪些决定。

## 2. 材料与事实

先确定要解释的行为。沿当前版本的实际路径核对核心步骤，依赖模块查到足以解释结果的位置，与外部系统交互时核对接口、数据格式和调用次序。读原始材料支持结论的那一段，记录版本、日期、位置和适用条件。会议摘要和二手资料可以提供线索，重要数字和决定要回到原始记录确认。

| 陈述 | 读者复查所需的材料 |
| --- | --- |
| 当前实现 | 仓库、commit、文件位置和决定行为的条件 |
| 建议的设计 | 目标、约束、已确认的决定和待决定事项 |
| 待验证的假设 | 欠缺的证据、验证方式、假设改变会影响的结论 |
| 实测结果 | 命令、输入、版本、环境、统计范围、原始输出 |
| 推导结果 | 前提、公式、单位和中间计算 |

资料互相冲突时先核对版本、配置和所指对象。引用放在支持的陈述附近。性能数字写出比较对象和计时起止，构造的数据明确标成示例。

## 3. 概念、层次与贯穿示例

从核心对象、改变它的动作和持续成立的约束中找出能概括全篇的模型。用正常和边界情况检查分类能否覆盖具体场景，容易重叠的类别要说明判别条件。概念按依赖顺序引入，说明它的用途、定义和例子。易混淆的名称用同一个对象对照。

例如，虚构任务 `export-17` 依次经过提交、生成、下载。提交返回的任务编号能用来查进度，下载地址在文件就绪后才出现。用同一编号解释状态和失败路径。若生成失败，读者仍可用编号查询原因。这个例子也能检验前面的概念表有没有把任务编号和下载地址混用。

开头先给定位，再给整体图景，每节只放大其中一部分。结尾交代这个结果引出的下一个问题。长文可按角色标出阅读路径。流程较长时，在每一步记录谁操作、读写哪些记录、状态如何变化。用总览表核对相同编号、时间和单位。比较两个场景时一次只改变一个相关条件。

## 4. 按内容选择讲法

| 要解释的内容 | 写到什么程度 |
| --- | --- |
| 结构 | 把组件放回系统全景，写出它满足的需求、保存的数据、调用方和责任边界。让一份输入沿接口穿过系统。 |
| 过程 | 给出一次完整执行。逐步交代触发条件、参与者、输入、结果和下一步由谁接手。说明错误最初在哪产生、怎样传递、最后由谁处理。 |
| 状态 | 选一个对象走过状态转换。列出每次转换的事件、前提和可见结果，包含失败或终止状态。 |
| 并发 | 标出每个参与者读写的数据、同时发生的动作和同步点。演示缺少某个同步点时的一种具体执行次序及其结果。 |
| 数量关系 | 先讲产生这个量的过程，定义符号、单位和取值范围。逐步推导，代入一组数值，改变一个条件检查结论。估算与实测分别交代依据。 |
| 设计取舍 | 将可行方案放在同一组具体需求下比较。给出选择、代价和依据，说明什么条件改变时应换方案。 |
| 源码与配置 | 固定版本并沿真实调用顺序讲解。每处节选前说明上下文，节选后解释输入、关键分支和可见结果。配置给出默认值及修改后的行为。 |
