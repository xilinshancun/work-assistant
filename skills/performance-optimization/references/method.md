# 方法与贯穿示例

## 0. 贯穿示例（虚构）

**TrainLoop** 是一个虚构的训练服务，每个训练步按以下顺序进行：

1. 一个特征服务（生产者）依次为两个 worker 各生成一份 5 GB 的特征；
2. 生产者把特征发布到共享存储；
3. 两个 worker 各自读入特征，完成一次前向、反向和优化器更新；
4. 客户端收到完成回执，再提交下一步。

目标与约束：

- **现状**：稳态步长中位为 26.0 秒。
- **目标**：低于 22 秒。
- **正确性**：每一步的 loss、分母和梯度范数必须与参考实现逐步相等。

**Ask** 是一个虚构的在线推理服务，用来演示负载与尾延迟。

本文所有数字都是演示，不对应真实系统。

## 1. 指标、负载和护栏

- **主指标**是用户等待的端到端量，例如一次正确更新的时间、某负载下的 P99 延迟、单位成本的成功吞吐。TrainLoop 的主指标定义如下：
  - 记客户端收到第 i 步完成回执的时刻为 Eᵢ；
  - 取 E₃−E₂ 到 E₃₂−E₃₁ 这 30 个间隔的中位数；
  - 首步和尾部单独报告。
- **正确性不变量**写成可机器检查的形式，例如逐步数值相等、张量摘要相同、测试全部通过。
- **护栏**是不能变坏的次要量：显存和主机内存峰值、存储峰值、失败率、首步时间和成本。任一护栏越界，候选就淘汰，与主指标好坏无关。
- **负载**要固定：请求组成、长度分布、并发数或到达率、缓存冷热。离线任务固定输入批次。没有固定负载，慢样本就说明不了业务瓶颈。
- **局部指标**只用于诊断，例如 kernel 时间、GPU 利用率和缓存命中率。

**Ask 小例（虚构）。** 负载固定为峰值到达率 400 req/s，请求组成与线上一致，P99 护栏为 200 ms。候选是"把批大小从 8 调到 16"。成功吞吐提高了 18%，P99 却从 180 ms 升到 260 ms。护栏越界，候选按事先写好的条件淘汰。

**尾延迟（tail latency）。** 一个请求扇出到很多副本时，任一副本变慢都会拖慢整体，所以要报分位数，不能只报均值。可选的缓解办法有对冲请求和副本隔离，见 Dean 与 Barroso 的 *The Tail at Scale*。

## 2. 在时间线上找关键路径

先取一条真实的慢样本，记录每一段的开始和结束。记录内容包括主机事件、设备事件、请求 ID、rank 和操作 ID。再用多条样本确认这条路径出现的频率。只看一条样本，可能把偶发现象当成瓶颈。

| 问题类型 | 先看什么 | 方法或工具 |
| --- | --- | --- |
| 系统资源 | 每个资源的利用率、饱和度和错误 | USE 方法（Brendan Gregg） |
| GPU 计算 | 计算、显存带宽、开销三者谁占主导 | Horace He 的三分法 |
| GPU 时间线 | 空闲时间分为主机等待、kernel 等待和其他等待；另看每个 rank 的通信与计算重叠比例 | PyTorch Holistic Trace Analysis |
| 分布式 | 每一步最慢的 rank，以及各个协调点（集合通信、准入） | 按 rank 对齐的时间线 |
| 生产者与消费者 | 生产者节拍、提交窗口、从发布到可读的间隔 | 跨进程按同一个键对齐的事件 |

区间互相重叠时不能相加，否则会重复计时。"RPC 已返回"也不等于"数据可读"，发布还要时间。

**TrainLoop 第 16 步的时间线（虚构）** 显示了四点：

- 生产者一次只服务一个请求，两份特征依次各用约 8.2 秒；
- 从发布到可读约 1.2 秒；
- worker 读入并校验约 2.2 秒；
- 训练计算与下一步的采集重叠。

30 个稳态步里，两个 worker 在开始准备时同时拿到特征的次数为 0。所以瓶颈在生产者，以及"下一步的请求何时发出"，不在训练计算。

## 3. 先估上限，再算值不值

**上限。** 只有暴露在关键路径上的时间能省下来。设某段占步时的比例为 p，把它加快 s 倍，整体最多加快 1 / ((1 − p) + p / s)。

尺度感的例子：AlphaEvolve 把 Gemini 训练中的一组 kernel 平均提速 23%，对应总训练时间缩短 1%。

**在线服务还要算排队。** 服务时间缩短后，请求释放资源更早，排在后面的请求也少等。在高利用率下，这部分间接节省可能比直接节省更大。所以要分别估算两部分：一是关键路径上的直接节省，二是利用率下降带来的排队变化。估算结果都以固定负载下的实测为准。

动手前用量级估算淘汰弱候选，见 Dean 与 Ghemawat 的 *Performance Hints*。

**TrainLoop 的估算（虚构）：**

```text
两份特征串行生成  2 × 8.2 = 16.4 s
发布到可读                  1.2 s
读入与校验                  2.2 s
估算步长                   19.8 s   之后实测 20.7 s，未解释约 0.9 s
```

这个估算由不同步骤的代表值拼成，只是推导，不是因果证明。未解释的差额要如实保留。

**值不值。** 把每次节省换算到同一单位，再和成本比较：

- 每次节省的资源 × 某时段内的预计执行次数 = 该时段的收益；
- 成本包括工程时间、实验资源和长期维护；
- 新增的分支、依赖、诊断难度和故障模式都算成本。

例：TrainLoop 每月约 10 万步，每步省 4.7 秒，作业占 6 张 GPU，约合每月 780 GPU·h。

正确但收益低的候选可以直接关闭。决定人也可以因收益不足而保留基线。

## 4. 候选卡

每个候选只改变一个因素，并在运行前写好这张卡：

```text
候选：<一句话>
只改变：<一个因素>；冻结：<版本、输入、配置、起始状态>
机制预言：<哪个区间> 从 <a> 降到 <b>          （用于核对机制，不单独决定放行）
主指标预期：<x–y>
无效线：主指标没有好过 <c> 即判无效          （硬判据；耗时类写"≥ c 无效"，吞吐类写"≤ c 无效"）
护栏：<数值、显存、P99、失败率> 保持 <条件>   （硬判据）
淘汰条件：<任一出现即否决，例如故障路径新增阻塞>
回滚：<怎样恢复基线>
```

放行只看硬判据：无效线、护栏和淘汰条件。预期区间和机制预言用来检查对瓶颈的理解是否正确。

**TrainLoop 的三个候选（虚构）：**

1. **客户端保持三步在途。** 下一步的工作因此已在服务端排队，客户端的往返从关键路径上移走。主指标预期为 20.5–21.5 秒，无效线为 22 秒。实测 21.3 秒，数值逐步相等，满足硬判据。
2. **worker 在步间协调前就发出下一步的采集请求。** CPU 回放发现一个故障路径：生产者只有一个槽位，发生故障转移时，提前发出的请求占住了槽位。当前请求的重试因此多等约 1.3 秒，而基线不到 1 毫秒。这违反"故障路径不得新增阻塞"，候选被否决。
3. **用 abort 抢回槽位。** 生产者在一次完整预填充结束前不会释放槽位，abort 不起作用。这个候选暂缓，要等生产者支持可抢占的采集。

这三个候选说明一件事：凡是声称"更早发就更快"的方案，都要先在故障路径上回放。

## 5. 便宜层先挡错误

- **正确性。** 同一输入下与参考实现比对，覆盖多种形状、取值和边界。
- **故障路径。** 回放超时、重试、故障转移、部分失败和重启恢复，比较与基线的排队顺序和阻塞时长。
- **资源。** 检查峰值内存和存储、泄漏，以及清理是否完成。

这一层全部通过后，才申请昂贵的真实负载。

## 6. 判定、复现和反例

- **判定**按事先登记的协议进行，见[测量](measurement.md)。
- **复现。** 在新样本上再跑一次，新样本指未参与选择的样本。TrainLoop 用第二批 64 条新序列复现，候选得到 20.7 秒。两批之间的差值不能算作候选的收益，因为输入和节点都变了。
- **反例库。** 记录每个被否决的候选、否决依据和复现方法。新方案先在这些场景上回放。
- **预言落空。** 硬判据通过而机制预言落空时，实测结果照常记录，但不能拿原来的机制解释去推广这个结论。这时要做三件事：
  - 修正机制模型；
  - 登记新版本的预言；
  - 在新样本上复现。

  复现通过后，才能把候选设为默认。任何情况下都不要事后放宽判据。

## 7. 交付与防回归

**交付物：**

- 结论，带比较对象和区间；
- 证据收据；
- 限度，即还没有验证什么；
- 下一步。

**留下回归检查：**

- 可重跑的代表性负载；
- 基线版本；
- 护栏；
- 触发复查的阈值；
- 负责人。

**线上服务**还要写明观察窗口、流量变化和回滚条件，并分阶段发布。生产环境中的细小回归也值得追：Meta 的 FBDetect 报告能在噪声中检出 0.005% 的回归。但阈值要按本服务的噪声来定，不能照搬。

**离线任务**在后续版本上重跑同一基准。

## 8. 什么时候停

- 剩余可省的暴露时间小于测量分辨率，或收益抵不上成本。
- 剩余瓶颈要改变产品约束，例如允许故障路径有界阻塞，或改变数值基线。这时转交决定人。
- 发现自己落入 Brendan Gregg 列出的反面方法时，回到第 2 节：
  - 随机改动；
  - 只用手边工具的路灯法；
  - 归咎他人；
  - 只跑不分析的被动基准。
