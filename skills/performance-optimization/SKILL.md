# 性能优化

本 skill 把"更快，且结果不变"的目标变成可以裁决的实验，并交付可复查的证据。示例使用虚构的训练服务 TrainLoop 和推理服务 Ask，数字均为演示，详见[方法](references/method.md)。

动手前先写下三件事：
- 用户最终等待的那个数，例如一次正确训练更新的时间，或峰值负载下 P99 达标的成功吞吐；
- 不允许改变的东西：数值结果、测试，以及显存和容量上限；
- 比较对象：同一输入、同一硬件上的当前版本。

三项缺一，就先补齐，再改代码。

## 1. 主线

1. **定指标、负载和护栏。** 固定请求组成，以及并发或到达率。写下主指标和正确性不变量。任一护栏越界，候选即淘汰。见[方法](references/method.md) §1。
2. **在时间线上找关键路径。** 用多条真实样本，把时间分成计算、数据搬运、开销和等待。重叠的区间不能相加。见[方法](references/method.md) §2。
3. **先估上限，再算值不值。** 只有暴露在关键路径上的时间能省。用每次节省乘以预计执行次数，再与工程、实验和维护成本比较。见[方法](references/method.md) §3。
4. **一次只改一个因素。** 候选卡写明改哪一段、预计缩短多少，以及判为无效的硬线。还要写维持哪些护栏、出现什么就淘汰、怎样回滚。放行只看硬判据。见[方法](references/method.md) §4。
5. **先在便宜层挡住错误。** 正确性测试、故障路径回放和资源检查通过后，才上真实负载。见[方法](references/method.md) §5。
6. **按事先写好的协议测量。** 同一输入下配对或交错运行，按方差来源分配重复，报告效应量和置信区间。见[测量](references/measurement.md)。
7. **在新样本上复现。** 新样本指未参与选择的样本。同时保留失败证据和被否决的候选。见[方法](references/method.md) §6。
8. **交付并防止回归。** 交付以下内容，见[方法](references/method.md) §7：
   - 结论、比较对象、区间和限度；
   - 可重跑的代表性负载和基线版本；
   - 护栏、回归阈值和负责人。

## 2. 多个 agent 一起做

- **提出者不判定自己的候选。** 至少把实现和评测分给不同会话。评测者给出技术判定，决定人签署采纳；对外发布和产生费用由用户批准。见[分工](references/agents.md) §1。
- **子 agent 只看得到简报。** 写清目标、交付格式、可用工具与来源、边界、停止条件和预算。见[分工](references/agents.md) §2。
- **协议先于数据。** 预先登记指标、负载、判据和预言。看到结果后要改，就另立版本并说明原因。见[分工](references/agents.md) §3。
- **结论只认收据。** 原始观测带路径、SHA-256、时间、产生者和输入版本，评测者能独立复算。见[分工](references/agents.md) §3。
- **状态写在磁盘上。** 进度日志、交接文件和 git 记录让新会话能接手。见[分工](references/agents.md) §3。
- **按依赖选择编排方式。** 依赖少的工作并行，共享上下文多的工作串行。资源的申请、启动和归还由同一个运行者负责。见[分工](references/agents.md) §4。
- **AI 生成的候选更要防作弊。** 评测程序与候选隔离，输入隐藏且多样。输出必须物化，计时要归属到候选本身。见[测量](references/measurement.md) §5。

## 3. 停下请人决定

- 需要越过授权的资源、费用或外部动作。
- 要放宽正确性判据或护栏，或者故障路径会新增阻塞。
- 剩余收益抵不上新增的复杂度，而保留基线与否涉及产品取舍。
- 预言连续落空时，先重查机制。只有需要改变产品约束或授权时，才转交决定人。
